# AGENTS.md

## Project Overview

Go learning project — REST API wrapper/binding for imageboard APIs (Danbooru, Gelbooru, Rule34).
Stack: Fiber v3, Redis (Keyv-equivalent caching), Swagger (swag + swaggerui).

## Locked Decisions

- **Framework**: Fiber v3 — chosen for Express/Hono-like API familiarity
- **Cache**: Redis via `go-redis/v9`
- **Docs**: `swag` CLI + `gofiber/contrib/swaggerui`
- **Runtime**: Go 1.26.4
- **Config**: `.env` via `joho/godotenv`
- **Task Runner**: `Taskfile.yml` (Task CLI) — replaces Makefile/Mage
- **CI/CD**: GitHub Actions (Lint, Auto-Release, Docker GHCR Push)
- **Container**: Multi-stage Alpine Docker build

## Rules for Agents

### General
- Always back claims with official docs or source code — no guessing
- If unsure, say so explicitly rather than hallucinating behavior
- All code must compile — do not leave placeholder stubs that break `go build`

### Swagger / swag
- Swag generates docs from **comments**, not types — always annotate handlers
- Run `swag init` from project root after any handler change
- Never manually edit `docs/` folder — it is always regenerated
- Required annotations on every handler:
  ```go
  // @Summary
  // @Tags
  // @Produce json
  // @Param
  // @Success
  // @Failure
  // @Security ApiKeyAuth  <-- MUST INCLUDE if endpoint is protected
  // @Router
  ```

### Authentication & CORS
- **Global Auth**: An `API_KEY` loaded from `.env` is required for protected routes via query `?api_key=` or header `Authorization: Bearer`.
- **Protected Group**: `/api/*` endpoints are protected (except for the media proxy `/api/rule34/media` which remains public).
- **CORS**: Fiber's CORS middleware is enabled globally (`app.Use(cors.New())`), allowing all origins to consume the API.

### Config & Versioning
- `AppVersion` is a `var` inside `config/config.go` to allow dynamic `ldflags` injection during compilation (`task build` / Docker).
- Do not use `const` for `AppVersion`.

### Redis
- Redis client is initialized once in `cache/redis.go` and shared via dependency injection
- Cache key format: `provider:resource:param` — e.g. `danbooru:posts:landscape`
- Default TTL: 5 minutes — adjust per endpoint if needed
- Always handle cache miss gracefully (fetch from upstream if miss)
- Do not store raw HTTP response — store parsed struct as JSON

### HTTP Client (upstream APIs)
- Use `net/http` standard library — no third-party HTTP client needed
- Always set a timeout on the HTTP client (default: 10s)
- Return structured errors — do not panic on upstream failure

### Models
- `models/Post` is the normalized shared struct — map each provider response to this
- Provider-specific raw structs go in `providers/` — not in `models/`

### Error Handling
- Use Fiber's error handler — return `fiber.NewError(status, message)`
- Never return raw Go errors to the client

## Common Commands

Using Taskfile (`task -l` for all commands):

```bash
# run development server with hot-reload (air)
task dev

# build optimized production binary
task build

# run linting (golangci-lint)
task lint

# show application version
task version

# generate swagger docs
swag init

# tidy dependencies
go mod tidy
```

## Provider API References

| Provider  | Base URL                              | Auth         |
|-----------|---------------------------------------|--------------|
| Danbooru  | https://danbooru.donmai.us/posts.json | API key (optional for SFW) |
| Gelbooru  | https://gelbooru.com/index.php        | API key (optional) |
| Rule34    | https://api.rule34.xxx/index.php      | None         |

Query param pattern (all three use similar conventions):
- `tags` — space-separated tag filter
- `limit` — number of results (max varies per provider)
- `page` / `pid` — pagination
